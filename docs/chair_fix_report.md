## 2. 原因（由程式與控制圖推論，未做對照實驗）

1. **餐椅在控制圖裡是小沙發。** `camera_projection.py` 把 `chair` 與沙發、扶手椅歸同一類 `seat`：0.45 m 實心座墊＋椅背板＋左右各 14% 寬的實心扶手塊。沒有椅腳、沒有鏤空椅背，FLUX 只能自己編細節。
2. **椅子與桌子輪廓黏在一起。** 餐椅貼著桌邊，投影後深度接近、canny 輪廓相連。
3. **控制太早結束。** depth 只控到 40%、canny 到 55%（`core/config.py` 的 `FAL_DEPTH_CONTROL_END`、`FAL_EDGE_CONTROL_END`），椅腳、欄桿等細節在後段成形時已無控制。
4. **prompt 未約束椅子款式**（推測，尚未查證 composed_prompt）。

## 3. 已做的修改

`designbridge/layout/camera_projection.py` 的 `furniture_parts` 新增 `chair` 專用形狀：

- 薄座面（0.05 m 厚）＋四隻細腳＋薄椅背，不畫扶手塊。
- footprint 四周內縮 5%，椅子與桌面輪廓之間留縫。
- `armchair`、`sofa`、`stool`、`bench` 等其他座椅形狀不變。

未做：第 3 點的 prompt 同款式限制（可能限制使用者想要的混搭椅型，需做成條件式，見第 5 節）、調高 `CONTROL_END`。

觀察（目視，沒有量化指標）：

- **12 張全部沒有出現第 1 節那種糾纏、融合、無腳的崩壞，舊形狀也沒有。** 這批沒有重現原本的問題，所以無法證明「修好壞椅子」。
- **新形狀確實改變了椅子的類型。** 舊形狀常被畫成有厚扶手的單椅（dining6 seed 777 最明顯：厚軟墊扶手椅擠在桌邊）；新形狀多是細腳、無扶手的餐椅（dining6 兩組、studio4 seed 11 的椅腳較清楚）。
- **新形狀不一定更好看。** dining6 seed 11 的新椅子偏細、像積木；studio4 seed 11 新圖右側的椅子結構比較怪，床區也和舊圖不同。
- **兩種形狀的整體構圖有時差很多**（living_dining seed 11 的沙發與茶几配置不同），因為控制圖一改，整個取樣就會偏移，不是只有椅子變。
- 近景椅子被畫面邊緣裁切的情況（living_dining）兩種形狀都有，這個與形狀無關。

結論：目前可以確認的只有「新形狀讓餐椅更像餐椅（有腳、無扶手）」；「減少崩壞」沒有被這批圖證實。第 1 節的壞圖是別的流程或設定產生的，還沒重現。

### 4.4 這批圖與使用者貼圖看到的問題

| 類型 | 例子 | 推測原因 |
|---|---|---|
| 桌子形狀與需求不符 | round6 要求圓桌，兩張都是長方形桌；long8 要求八人長桌，畫出近似正方形的桌子 | 控制圖裡所有桌子都是長方形加四個角落桌腳（`furniture_parts` 的 `table`），沒有圓桌或長桌的形狀 |
| 家具數量／種類與平面圖不符 | loft6 舊圖沒有餐桌與餐椅，只有書桌與圓凳；small4 新圖出現兩台電視；long8 舊圖多出橘色單椅；wood6 要求 6 椅只看到約 4 張 | 控制 scale 低、結束早，遠處與被裁切的家具模型自行發揮；提示詞也會讓模型補家具 |
| 分不清是椅子還是桌子 | small4 前景右下的物體（桌面與椅背疊在一起）；loft6 新圖下緣的黑色大塊；使用者貼圖中桌面與地磚同色，桌子融進地板 | 近景家具被畫面切掉一半又放大，座面、桌面輪廓重疊；桌面顏色接近地面 |
| 椅子與桌子黏在一起 | 使用者貼圖第二張：金框椅子與橢圓茶几交疊 | 椅子貼著桌邊，輪廓相連 |
| 缺腳或腳數不對 | 使用者貼圖茶几少一隻腳；modern4 新圖餐桌只見一隻粗桌腳 | 桌腳細，後半段去噪沒有控制，模型會省略或合併 |
| 物件錯置 | small4 舊圖落地燈頂端長出冷氣機；電視被畫進櫃子裡又另一台電視 | 同上，非家具類別的細節沒有約束 |

新形狀對椅子本身有幫助：long8、loft6、modern4 的新圖餐椅更像餐椅（有腳、無扶手），且 long8 的過大椅子由 2 張降為 0 張；loft6 舊圖整組餐桌椅消失，新圖有出現。round6、wood6 兩者幾乎相同；small4 新圖出現重複電視。整體改善有限，沒有消除上表的問題。

### 4.5 提示詞修改後重生（用使用者貼的平面圖座標重建）

條件：把使用者貼的平面圖（沙發、扶手椅、茶几、邊桌、3 張椅子無桌、書櫃、電視櫃、盆栽）依像素換算成座標，房間假設 4.5×4.5 m；同一份佈局與 seed（3、99），差別只有 composer 提示詞規則（舊＝色碼＋「把風格顏色套到家具」；新＝色名、accent 不套主要家具、同種家具同款式、只檢查可見家具）。左＝舊、右＝新。

| | 舊提示詞 | 新提示詞 |
|---|---|---|
| 椅子 | 兩張圖都**看不到椅子**：seed 3 的椅子變成後面餐廳裡的綠椅，seed 99 變成綠色圓凳 | 兩張圖都有椅子（seed 3 是木椅加白色躺椅，seed 99 是兩張扶手椅） |
| 顏色染到家具 | seed 3 出現綠色扶手椅、seed 99 出現綠色圓凳（提示詞的 sage green accent） | seed 3 沒有綠色家具；seed 99 的椅子仍偏淡綠 |
| 與平面圖是否對得上 | 都不對：沙發位置與方向、椅子數量、電視位置與平面圖差很多 | 也不對：seed 99 的沙發在右後、書櫃變成佔滿左牆的大書櫃 |

結論：
- 提示詞改動對「椅子有沒有出現」與「顏色染到家具」有幫助，但樣本只有 2 個 seed。
- **佈局與平面圖對不上沒有因此解決。** 深度圖是對的，但生出來的圖仍然把沙發、書櫃移位，說明主因是控制權重偏弱（depth 0.3、canny 0.3），不是提示詞。
- 這個重建場景的 10 件家具投影後全部可見（我假設的房間尺寸與相機和使用者的不同），所以「畫面外的家具不要求提示詞提到」這項改動**沒有被這次測試用到**。

> **路徑說明（同日補充）**：4.1、4.2、4.3 的對照圖是我強制 `hint_layout=true` 跑的，走的是**投影深度流程**（Depth 0.3/0.7 ＋ Canny 0.3/0.7），不是使用者主要使用的平面圖／CAD（Union）路徑。只有 4.5 走 Union 路徑（canny 0.35/0.55 ＋ depth 0.3/0.4），但那組同時改了提示詞。因此椅子形狀的改動在 CAD 路徑上的效果**還沒有單獨驗證**。

## 5. 下一步

1. 用同一個 seed、同一個餐桌場景重生，比較修改前後（會呼叫 fal，產生費用，需要你同意）。
2. 若椅腳、椅背仍崩壞，試調高 `FAL_DEPTH_CONTROL_END` 與 `FAL_EDGE_CONTROL_END` 各約 0.15，另做一組對照。
3. 若近處與遠處椅子款式仍不一致，再加 prompt 限制，且只在「同場景 2 張以上 `chair` 且使用者原話未指定椅型」時套用，不影響 `armchair`、`stool`、`bench`。
