# 室內設計文字輸入範例集(依 requirement_analyzer 的路由情境分類)

分類依據是 [requirement_analyzer.py](designbridge/core/prompts/requirement_analyzer.py) 實際的判斷規則，
每一類開頭都標好「預期的 routing_decision / hint_layout / hint_style」，可以直接拿來當消融實驗的
ground truth：把 prompt 丟給 Gemini/Qwen 跑 `_call_llm_requirement_analyzer`，比對輸出的
`routing_decision`、`hint_layout`、`hint_style` 是否跟這裡標的一致，就能算「路由判斷準確率」。

**⚠️ 每句後面括號裡的文字是給人看的注解（解釋這句在測什麼），不是 prompt 的一部分。**
複製這些句子去餵模型時，只取句號之前的內容，括號整段都要拿掉——不然注解本身的文字
（例如「隱含限制條件」「邊界案例」這種術語）混進去，會污染輸入，模型會被那些額外的字影響判斷，
測出來的就不是「這句話本身」的效果了。

---

## 情境 1：從零開始打造 + hint_layout = TRUE
**預期：`routing_decision = "design"`、`hint_layout = true`**

觸發條件：句子裡出現具體的家具**位置、朝向、相對關係**，或明確要求擺放/移動/重排
（例：「A 在 B 的左/右/旁邊/對面」「放/擺/移到…」）。全新設計或整體重新規劃都算，
不需要已經有上傳照片。

1. 床放右邊靠窗，衣櫃放左邊，書桌移到床跟衣櫃中間。
2. 沙發面對電視牆放，茶几放在沙發前面，兩張單人椅分別放在沙發兩側。
3. 書桌靠窗放，旁邊放一個書櫃，椅子朝向書桌。
4. 床頭靠牆放，床尾留一個梳妝台的位置，衣櫃放在門的旁邊。
5. 客廳沙發跟電視牆對放，中間放茶几，角落放一盆大型植物。
6. 請規劃一個陽台休閒區，兩張椅子放窗邊，中間夾一張茶几，可喝茶看書。
7. 幫我設計給兩個小孩共用的房間，上下鋪靠牆放，各自的書桌放在床邊窗下。
8. 玄關進門左手邊放鞋櫃，右手邊放一張穿鞋椅，正對面掛一面全身鏡。
9. 廚房中島放在流理台正對面，中島兩側各留一張吧檯椅的空間。
10. 主臥床放在採光最好的那面牆，床頭兩側各放一個床頭櫃，衣櫃放在床尾對面。

**口語模糊版**——一樣有明確位置詞，但講法比較像真實使用者隨口說的，不是條列指令，
測模型能不能從鬆散的口氣裡還是抓到 hint_layout 該是 true：

11. 床大概放右邊靠窗那邊好了，衣櫃放左邊，書桌喬到床跟衣櫃中間就好，其他我沒什麼想法。
12. 沙發應該要對著電視牆吧，茶几就放沙發前面，其他家具你看著辦。
13. 書桌可能靠窗會比較好，旁邊隨便放個書櫃就好。
14. 就床頭靠牆，其他我沒特別想法，喔對了衣櫃記得放門邊。
15. 大概是沙發跟電視對放這樣，中間有個茶几就好，角落感覺可以放盆植物。

## 情境 2：從零開始打造 + hint_layout = FALSE
**預期：`routing_decision = "design"`、`hint_layout = false`、`hint_style = true`**

觸發條件：只講風格、材質、色彩、氛圍、光線，**完全沒有指定家具的位置關係**。

1. 我想要北歐極簡風的餐廳，白色牆壁搭配淺木色家具，整體乾淨清爽，有大量自然光。
2. 幫我設計一個日式侘寂風的臥室，大地色系、粗麻布料、低矮床架，安靜有禪意。
3. 想要輕奢風格的餐廳，黑色鐵件餐桌搭配絲絨餐椅，大理石紋牆面，金色吊燈。
4. 我喜歡台式懷舊風，老木窗、復古磁磚地板、溫暖燈光，感覺有老台灣的人情味。
5. 我想要法式奶油風客廳，奶白色牆面、弧形沙發、黃銅細節與柔和燈光。
6. 幫我把客廳改成北歐風，喜歡白色和木質感，希望光線充足。
7. 我最近工作壓力很大，想要一個回家就能立刻放鬆的客廳，不知道該怎麼設計。
8. 隨便幫我弄一下客廳，看起來舒服一點就好。
9. 家裡感覺很亂、很壓迫，我也不知道問題在哪，就是希望看起來清爽一點。
10. 我想讓家裡看起來更有品味，但又不想太制式，感覺自然一點比較好。

**更模糊版**——連風格詞都不給，看模型敢不敢在完全沒資訊的情況下還是判成 hint_layout=false
（因為就算模糊，這幾句也還是沒有提到任何家具位置）：

11. 家裡感覺有點舊了，想換個感覺，不用很特別。
12. 客廳可以弄漂亮一點嗎，我也說不出想要什麼。
13. 就是想讓家裡看起來不一樣，其他隨便你發揮。
14. 最近想改造一下臥室，但還沒想清楚要什麼樣子。

## 情境 3：局部修改
**預期：`routing_decision = "design_adjuster"`、`hint_adjuster = true`**

觸發條件：針對**畫面中已經存在的某個物件**做移除、替換或改色，不影響整體空間感。
這條路徑要有照片、且照片裡要能框出對應的物件——沒有對應現存物件的「新增」或「移動到某位置」
一律不算這一類（要歸到情境 1）。測試時務必搭配一張確實有該物件的房間照片。

1. 把桌上的電腦移除。
2. 把沙發換成藍色。
3. 移除窗邊那盆植物。
4. 把牆上的畫換掉，換成風景畫。
5. 把椅子換成木頭材質的。
6. 那盞立燈拿掉，沙發換成灰色的就好，其他都不要動。
7. 把地毯換成深色的。
8. 把窗簾換成白色薄紗的。
9. 移除電視櫃上的雜物擺飾。
10. 把餐桌的顏色換成黑色。

## 情境 4：邊界測試（容易被誤判的案例）

用來檢查模型會不會把「新增/移動家具」誤判成局部修改，或把「單一物件改色但影響整體氛圍」的
案例判斷錯——這幾句故意設計得模糊，Gemini 跟 Qwen 在這裡的判斷差異最值得記錄。

1. 床的右邊加一個櫃子。（新增家具＋指定位置 → 應為情境 1，不是局部修改，即使聽起來像小改動）
2. 在天花板加一盞燈。（新增，非既有物件 → 情境 1）
3. 把電視牆整個拆掉改成一整面書牆，其餘家具位置都不要動。（結構性改動，不是單純物件替換，邊界案例）
4. 我要工業風客廳，但家具要淺色系、質感要輕奢一點，不要太粗獷。（風格描述但帶有矛盾修飾，測 hint_style 判斷）
5. 家裡有輪椅使用者，客廳動線要夠寬，但我還沒想好要選哪個風格。（隱含空間配置需求但沒有具體位置詞）
6. 家裡有兩個還在爬的小小孩，想把客廳重新規劃，也要留一塊地方讓他們玩。（隱含安全/收納限制，測能否推論出材質限制）
7. 老人要住的房間，家具不能有尖角，動線要寬敞好走，方便輪椅或助行器移動。（隱含限制條件，非直接風格/位置描述）
8. 只是想先看看效果，不用太認真，隨便給我一個溫馨一點的臥室就好。（極度模糊 + 弱化語氣，測模型會不會拒答或亂猜）

3. 把這張照片裡的桌子換成圓形的。（情境 3：針對既有物件的局部修改）
